## Повторюваність тесту

Оригінальний пакет R007 r002 збережено в `tests/recovery/r007/` з оригінальними контрольними сумами. Запускати на окремому прийнятному Docker-хості від `root`:

```bash
cd tests/recovery/r007
sha256sum -c SHA256SUMS
bash run_once.sh
```

**Примітка про pin:** історичний R007 harness навмисно клонує SHA `dcd164f…` та перевіряє точну GPG-копію. Не змінювати цей pin під час ретроспективного відтворення доказів. Для майбутньої версії системи зробити новий тест і новий акт приймання.

## Відновлення після аварії

1. Новий Debian: встановити залежності й клонувати GitHub за `README.md` і `docs/OPERATIONS_AND_RESTORE_UA.md`.
2. Перевірити Git commit, SHA зашифрованого архіву, виконати `install_restore.sh --dry-run`.
3. На **новому** сервері виконати `install_restore.sh --apply` без увімкнення таймерів.
4. Окремо розшифрувати архів GPG за паролем, який зберігається поза GitHub/сервером; перевірити SHA оригіналу. Відновити `.env` через `restore_private_config.py`; історичні логи — за потреби.
5. Перевірити фактичні накопичувачі/шляхи/Telegram, права `.env=0600`, юніти й календарі. Ввімкнення таймерів — лише окремим рішенням оператора. **`Persistent=true` може негайно запустити пропущені SMART тести.**
6. Зберегти новий звіт про фактичне відновлення.

## Межі закриття

- R005 підтвердив GPG SHA, еквівалентність ефективного токена Telegram, приватного `.env` та історію 1827 журналів у sandbox, без дій на живому диску. Див. `docs/ACCEPTANCE_R005_20261108_UA.md`.
- R007 підтвердив реальне **файлове** встановлення у свіжий Debian 12 Docker, але НЕ чисту VM із systemd PID1. Для додаткового високого рівня впевненості залишити окремий VM/hardware proof, коли це буде потрібно.
- Це знімок від **2026-11-08**, а не безперервна резервна копія. Нові конфігураційні зміни, журнали та релізи самі в GitHub не потрапляють.
- GitHub-репозиторій публічний, а шифрований архів доступний для офлайнового підбору пароля. Короткі чи передбачувані паролі можуть бути вразливими: рекомендовано зробити репозиторій приватним і надалі використовувати довгий випадковий пароль. **Паролі та токени в Git і звіти не додавати.**
- Цей документ і R008 **не змінюють** робочу інсталяцію, `systemd`, `SMART` чи суботній розклад на `s01`.
